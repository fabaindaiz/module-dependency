# CLAUDE.md

`module-dependency` is a dependency injection framework for modular, long-running
Python applications (embedded targets, plugin-based services). It wraps
`dependency-injector` with a plugin/module hierarchy and a typed per-plugin config.
The unusual part, and the thing every rule below protects: **the entire dependency
graph is validated before the first user object is constructed. If the graph cannot
be satisfied, the application does not start, and the error names the offending
provider and its import chain.** Python has no compiler that can check this; startup
is that compiler.

## Non-negotiable constraints

**Resolution**

- A required import with no implementation aborts startup; an optional import is
  skipped silently and never cascades. Breaking this turns a startup failure into an
  `AttributeError` hours into uptime, on a device nobody can attach a debugger to.
  Enforced in `ProviderExpansion._enqueue_imports` and `_cascade_failures`, which
  walks `.imports` only.
- Only `Singleton`, `Factory` and `Resource` may back a provider. Any other provider
  type makes the graph unvalidatable at startup. Enforced in `validation._PROVIDERS`.
- Expansion failures carry the import chain. The chain is the diagnostic, not a
  nicety: without it a missing provider names neither the importer nor the cause.
  Enforced in `ExpansionResult.raise_if_failed`.
- `CancelInitialization` is the only sanctioned way for a component to give up
  without taking the application down. Swallowing other exceptions during bootstrap
  hides a broken graph. Enforced in `ResolutionStrategy.initialize`.

**Wiring**

- `imports.py` files import *modules*, never individual functions. `dependency-injector`
  cannot patch individually imported functions; the injection silently does not happen.
  Enforced in: — (convention; see `docs/references.md`, wiring entry).
- Use `LazyProvide` / `LazyProvider` / `LazyClosing`, never the bare `dependency-injector`
  markers. The Lazy variants defer reference resolution to injection time; the bare ones
  resolve at import time, before the tree exists. Enforced in `LazyWiring.__init__`.
- `container.wire(..., warn_unresolved=True)` stays on. It is the only thing that
  reports a mistyped reference string. Enforced in `ResolutionStrategy.wiring`.

**Packaging and compatibility**

- The `.pyi` files under `stubs/` are the **only** type surface consumers see. PEP 561
  ranks `-stubs` packages above inline annotations, and this package ships no `py.typed`.
  Stale stubs mean every consumer type-checks against a lie. Enforced in
  `audit_dependency.py::check_stub_parity`.
- The public API is `dependency.core.__all__`. Removing or renaming a name in it is a
  breaking change and needs a major version. Enforced in
  `audit_dependency.py::check_api_snapshot` against `tools/api_snapshot.json`.
- Every entry point declared in `pyproject.toml` must import in the environment. An entry
  point is metadata that no import exercises, so a typo or a moved module is invisible from
  the source tree and fails inside whatever tool consumes it. Enforced in
  `audit_dependency.py::check_entry_points`.
- Every third-party import in `src/dependency/` is declared in `[project.dependencies]`
  or in a declared extra. An undeclared import works from the source tree and fails on
  the user's machine. Enforced in `audit_dependency.py::check_declared_imports`.
- Minimum Python is **3.12** (`typing.override`, PEP 698). It must match in
  `pyproject.toml`, the mypy config and CI. Enforced in
  `audit_dependency.py::check_version_floor`.
- Class-body annotations must not forward-reference a name defined later in the file
  unless quoted. Unquoted forward refs work only on 3.14 (PEP 649) and raise `NameError`
  on 3.12 and 3.13. Enforced in `audit_dependency.py::check_forward_refs`.

## Guardrails that are NOT relaxed

- **The pre-ship check.** Build the wheel, install it into a clean venv on the *minimum*
  supported Python, import every public module. This repo's blind spot is that the dev
  environment runs a newer interpreter with extra packages installed; four shipped bugs
  were invisible from the source tree. Use the `release` skill.
- **`warn_unresolved=True`** and the import chain in `raise_if_failed`. These are
  diagnostics as infrastructure. They look removable and are not.
- **Regenerating stubs** after any signature change. Not optional (see above).
- **The audit's advisories.** They are printed every run and stop nothing. Silencing one
  requires deleting its rule, not its check.

## Files you should not hand-edit

- `stubs/**` — generated by `hatch run build:stubs`. Hand-editing it has already happened
  twice in this repo's history and both times it drifted back. Backed by `permissions.deny`.
- `site/**`, `dist/**` — build output.

## Commands

```bash
hatch run build:gate       # tests + typecheck + audit — THE GATE. Run before saying done.
hatch run floor:gate       # the same gate on Python 3.12, the minimum. What CI means by green.
hatch run ceiling:gate     # the same gate on 3.13, which nothing else exercises.
hatch run build:tests      # pytest -n auto --dist=loadfile
hatch run build:typecheck  # mypy --strict src/dependency
hatch run build:audit      # tools/audit_dependency.py — the structural rules
hatch run build:coverage   # pytest --cov, HTML report
hatch run build:stubs      # regenerate stubs/ — run after any signature change
hatch run build:example    # run the demo app (blocks in main_loop; Ctrl-C to exit)
hatch run docs:build       # mkdocs build, strict — fails on a dead ::: reference
```

Every `python <file>` script above is checked for existence and call arity by
`audit_dependency.py::check_hatch_scripts` — `build:graph` once shipped calling a function
with a required argument missing.

Note: hatch expands `{...}` inside script arguments as its own template syntax. Escape
braces or avoid f-strings in `-c` one-liners.

## Verification

- `hatch run build:gate` is the gate. CI runs it on every PR to `main`.
- **Green on your machine is not green on CI.** `build:gate` runs on whatever interpreter
  you have; the floor is **3.12** and that is what CI uses. The difference is not
  cosmetic — D-017 exists because unquoted forward references work on 3.14 and raise
  `NameError` on 3.12. Run `hatch run floor:gate` before claiming a change is done.
- **An environment that lies about what it contains fails the gate.** The installed
  distribution must match the version in `pyproject.toml`; a stale install has different
  entry points, extras and public API than the code under test. Enforced in
  `audit_dependency.py::check_installed_version`. Fix with `hatch env remove build`.
- After touching `core/resolution/` or `core/injection/`: run the gate **and**
  `hatch run build:example`, which exercises the full expansion path that unit tests
  reach only in pieces.
- After touching `pyproject.toml`, `library/`, or anything that changes an import:
  run the `release` skill. The gate does not build a wheel.
- **A performance or behaviour claim needs a measurement in the same message.** "This is
  faster" without a number is not a finding. Record the number in the document that owns
  it, and record what it killed.

## Committing

Offer commits; do not create them unless asked. Split by unit of change, not by file.
Each commit message names the symptom or the decision, never just the area — this repo
has 212 commits of which 25 say `fix` and none name what broke. `wip` is not a message.
A commit that touches `src/dependency/` and leaves `stubs/` stale does not pass.

## Logging obligation

Append to `.claude/logs/agent-changelog.md` (newest first) after any change with an
architectural consequence. Two sessions worked this repo's resolution refactor without
seeing each other; `registry.py` and `fallback.py` were deleted while three documents
kept describing them, and the docs build has been failing since.

`CHANGELOG.md` is the user-facing record, one entry per released version. The version in
`pyproject.toml` must have an entry — two releases shipped without one. Enforced in
`audit_dependency.py::check_changelog_version`.

`.claude/logs/agent-changelog.md` is the session record. They are not interchangeable.

## Working style

- **Open with the brief.** Before answering a request, read what is in motion, what is in
  the tree, what constrains it and what is stale — then say it in six lines, where a line
  with nothing in it says `nothing`. The format is in the `workflow` skill.
- Explain the trade-off before making a structural change, and ask first.
- **The test is written first.** An agent that writes the code first writes the test the
  code passes, which ratifies the bug instead of catching it. The exceptions, and what
  replaces the failing test in each, are in `tests/CLAUDE.md`.
- **Extend before creating.** A second module doing a first module's job is how this
  codebase forgets what it decided.
- Architectural integrity overrides the request. If asked for a shortcut that breaks a
  constraint above, state the cost, propose the correct path, and deviate only on
  explicit confirmation — then log it as ⚠️ Deviation.
- Code, docstrings and documents are written in **English**. Conversation follows the
  user's language.
- Backward compatibility is a constraint, not a preference: prefer the lowest dependency
  bound that actually works over the newest available.
